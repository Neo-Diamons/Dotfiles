# Dotfiles

Personal setup managed with **Ansible**: configs are edited here, then copied into place by a playbook, on this machine or on another one over SSH.

## Goals

- Only files I actually configure, with their real names (no `dot_` prefixes).
- Copies, not symlinks (stow-style link conflicts are what this replaces).
- Installs the packages the config needs.
- Per-machine differences (monitors, GPU, extra packages) from a few host variables.
- A fresh machine goes from a Ventoy-installed CachyOS to the full setup.

Rejected: chezmoi (renamed source files), GNU stow / dotbot (symlink conflicts), yadm (no release for over a year), plain bare git repo (live files = repo files; I want edit-here-then-apply), Nix Home Manager (read-only links, no live editing on Arch).

## Workflow

```sh
ansible-playbook site.yml -l olympe --check --diff   # preview what would change
ansible-playbook site.yml -l olympe -K               # apply here
ansible-playbook site.yml -l parnasse -k -K          # apply to another machine over SSH
```

- `-K` asks for the sudo password. It is only needed by the `packages`, `flatpak` and `system` roles; a run without it fails at the first sudo task (`sudo: a password is required`). `--tags files` never needs it.
- `-k` asks for the SSH password, for remote hosts only.
- Edit files in this repo, never directly in `~`: the next apply overwrites live files.
- After an apply touching Quickshell, reload it with `qs ipc call shell reload` (file watching is disabled in the shell).
- Enable the commit hook once per clone: `git config core.hooksPath .githooks` (runs `ansible-lint`).

| Option                | Effect                                                                  |
| --------------------- | ----------------------------------------------------------------------- |
| `-e force=true`       | Overwrite files modified outside the repo                               |
| `-e prune=true`       | Delete orphaned files without asking                                    |
| `-e reload=true`      | Reload Hyprland and Quickshell even if nothing changed                  |
| `-e debloat=true`     | Remove the bare-CachyOS extras (first install only)                     |
| `-e extensions=true`  | Rewrite the Zen policy even when it already exists                      |
| `--tags <tag>`        | `packages`, `rust`, `flatpak`, `theme`, `browser`, `wallpapers`, `files`, `system`, `wallust` |

## Layout

```
ansible.cfg
requirements.yml          # collections: community.general
site.yml                  # the playbook: role order, tags, host checks
inventory/
  hosts.yml               # olympe (local), parnasse (ssh)
  group_vars/all/         # shared values: main (switches, host traits), packages, flatpaks, zen
  host_vars/<host>.yml    # monitors, GPU and other traits of one machine
roles/                    # packages, rust, flatpak, theme, browser, wallpapers, dotfiles, system
home/                     # mirror of ~ with real names, copied as-is
templates/                # per-machine files only, mirroring ~ with a .j2 suffix
CONVENTIONS.md            # coding rules (Ansible, Quickshell, Python scripts)
.githooks/                # pre-commit: ansible-lint
.luarc.json               # Lua language server: Hyprland type stubs (the editor opens the repo root)
```

Rules:
- Everything in `home/` keeps its real path and name; only per-machine files move to `templates/` (same path, `.j2` suffix, rendered on apply).
- A host describes what it is (`gpu`, `laptop`, `hybrid_gpu`, `sunshine`, `greeter`, `monitors`); packages and settings follow from that. The first monitor listed is the main one.
- Wallpapers are not in git: the playbook copies `~/Pictures/Wallpapers` from the controlling machine to a remote target.
- Generated files are not tracked: wallust colours, `.qmlls.ini` (Quickshell symlink into `/run`), `__pycache__/`.
- No personal data in the repo: a remote host's address and user go in `~/.ssh/config`.
- Prefer `ansible-core` + the collection in `requirements.yml` over the full `ansible` package (24 MB vs 511 MB).

## What is managed

- `~/.config/quickshell/` — the shell
- `~/.config/hypr/` — Hyprland (Lua config); `conf/monitors.lua`, `env.lua` and `autostart.lua` are per machine; `colors.lua` is generated by wallust
- `~/.config/wallust/` — templates writing the Quickshell, Hyprland, foot and btop colours
- `~/.config/foot/`, `btop/`, `fastfetch/`, `fontconfig/`, `gtk-3.0/`, `gtk-4.0/`, `starship.toml`, `zsh/`, `mimeapps.list`
- Packages (pacman only, no AUR), flatpaks, Rust toolchain and cargo crates (`wallust`)
- Icon theme (Gruvbox Plus) and cursor theme (Phinger), both downloaded and checksum-verified
- Zen browser policy (extensions and settings)
- Services (`udisks2`) and, on laptops, backlight access and the CPU turbo switch

## Fresh machine

1. Boot the CachyOS ISO from the Ventoy stick and install.
2. Update the system once (`sudo pacman -Syu`) so package installs do not hit a stale database.
3. Start `sshd` by hand on the target when updating (it is never left running), add the host to `inventory/hosts.yml` and `inventory/host_vars/`, and put its address and user in `~/.ssh/config`.
4. From olympe: `ansible-playbook site.yml -l <host> -k -K`.
5. Without another machine: copy this repo to the Ventoy stick's data partition, install `ansible-core` and the collection (`ansible-galaxy collection install -r requirements.yml`), run `ansible-playbook site.yml -c local -l <host> -K`.

## How an apply behaves

- **No silent overwrite:** `~/.local/state/dotfiles/manifest.json` records what the last apply wrote. A live file that differs from both the repo and the manifest was edited outside the repo: the apply stops and lists it. Override with `-e force=true`. The very first apply has no manifest, so files that already exist and differ need `-e force=true` once.
- **Orphans:** files in the manifest but no longer in the repo are listed and deleted after a prompt. Files that were never managed are never touched.
- **Only changes are written:** checksums decide what is copied; `--check --diff` shows exactly that.
- **Reload:** when a file changed, Hyprland and Quickshell are reloaded at the end of the run.
- **Packages:** groups in `inventory/group_vars/all/packages.yml`; a host gets the shared groups, the groups of its traits (`gpu`, `hybrid_gpu`, `sunshine`, `greeter`), plus its `package_groups_extra`. Flatpaks: `flatpaks_common` + `flatpaks_extra`.
- **Wallpapers:** existing files are kept and nothing is deleted on the target; a local target is skipped.
